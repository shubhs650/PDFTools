# Interop checklist (owner-run, Windows)

ARCHITECTURE.md §11 and ADR-001 B16: the agent prepares the files and this checklist, and the owner
runs it in **Adobe Acrobat Reader** (free) and **PDF-XChange Editor** (free mode). Record the
result per viewer as ✅ (works), ⚠️ (works with a prompt or cosmetic issue) or ❌ (broken), and add
notes.

## M0-S1 — saved files (D-03, D-06; [ADR-005](../../docs/adr/005-s1-incremental-save.md))

Files: [`e2e/fixtures/self-made/s1-interop/`](../fixtures/self-made/s1-interop/). They were
regenerated by `node spikes/s1-save/make-fixtures.ts && node spikes/s1-save/run-node.ts`. All are
self-made. The signature uses a throwaway test certificate (`signer-cert.pem`).

Each input `X` comes in four variants:

| File                 | What it is                                                                           |
| -------------------- | ------------------------------------------------------------------------------------ |
| `original__X.pdf`    | The input.                                                                           |
| `X__narrow.pdf`      | **Proposed Ctrl+S output:** original bytes + only the changed objects appended.      |
| `X__incremental.pdf` | PDFium's raw incremental save (reference; see ADR-005 for why it is not used as is). |
| `X__rewrite.pdf`     | Full rewrite (Save Optimized).                                                       |

Inputs:

- `plain`, `annotated` and `form` (AcroForm);
- `objstm` (object streams + xref stream);
- `encrypted-aes256` and `encrypted-rc4-128`: owner password `owner-s1`; print and extract
  denied, annotate allowed;
- `encrypted-noannotate`: annotations denied. It must contain **no** new annotations;
- `signed`.

Every edited file has one annotation per EmbedPDF tool on page 1:

- text markup: highlight, underline, strikeout, squiggly;
- insert text (caret) and replace text (strikeout with intent);
- pen (ink) and ink highlighter;
- circle, square, cloud (square) and cloud (polygon);
- line, arrow, polyline, polygon;
- sticky note, free text, callout;
- image stamp (red-bordered square) and link (to example.org).

The `form` variants also change the text field to "Edited by S1" and uncheck the checkbox.

### C. Reverse direction (their annotations, our save)

Once the S1 harness accepts files you supply:

1. In each viewer, add a few annotations of different kinds to `original__plain.pdf` and save.
2. Send the file back. The agent will open it with PDFTools' engine, add one markup, save with the
   narrow incremental path, and return it.
3. Reopen it in the same viewer: your annotations and replies must be unchanged, and ours visible.

## M0-S2 — measurements and scale viewports (D-14; [ADR-007](../../docs/adr/007-s2-measure-viewport.md))

Files: [`e2e/fixtures/self-made/s2-interop/`](../fixtures/self-made/s2-interop/). They were
regenerated by `node spikes/s2-measure/run-node.ts`. All are self-made. The sheet is one A1 page:

- **page scale 1:100**, in metres;
- a **"Detail A"** dashed region at **1:5**, in millimetres;
- a building drawn as a 200 × 100 mm rectangle (20 × 10 m real);
- a plate drawn at 80 × 40 mm (400 × 200 mm real) inside Detail A.

Measurements written by PDFTools, with the values we expect:

| Measurement             | Annotation / `/IT`           | Expected                 |
| ----------------------- | ---------------------------- | ------------------------ |
| Building long side      | Line / LineDimension         | 20.00 m                  |
| Building perimeter      | PolyLine / PolyLineDimension | 60.00 m                  |
| Building area           | Polygon / PolygonDimension   | 200.00 m²                |
| Plate long side         | Line / LineDimension         | 400.0 mm                 |
| Plate perimeter         | PolyLine / PolyLineDimension | 1200.0 mm                |
| Plate area              | Polygon / PolygonDimension   | 80000.0 mm²              |
| Building corner → plate | Line (crosses Detail A edge) | 22.20 m, flagged "spans" |

Files:

| File                            | Variant                                                                                        |
| ------------------------------- | ---------------------------------------------------------------------------------------------- |
| `s2-cap.pdf`                    | Measurement dictionaries + `/Cap true` + `/Contents` = value. Appearance draws lines only.     |
| `s2-freetext.pdf`               | As `s2-cap`, plus a FreeText label per measurement, grouped (`/IRT` + `/RT /Group`).           |
| `s2-noap.pdf`                   | As `s2-cap`, but the measurements have **no** appearance stream, so the viewer must draw them. |
| `s2-vp-only.pdf`                | The sheet with only the page viewports (`/VP`): no measurements. For D and F below.            |
| `s2-cap-edited-by-embedpdf.pdf` | `s2-cap` after a later PDFTools edit (colour change + a note). Measurement data must survive.  |

### D. Viewer checks (both viewers)

| #   | File / action                                                                                                                                                                           | Acrobat | PDF-XChange |
| --- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------- | ----------- |
| D1  | `s2-cap.pdf`: are the 7 annotations listed as **measurements** (Distance / Perimeter / Area) in the comments list or properties, with the expected value and unit?                      |         |             |
| D2  | `s2-cap.pdf`: is any value **visible on the page** without selecting the annotation?                                                                                                    |         |             |
| D3  | `s2-freetext.pdf`: labels visible; does moving a measurement also move its label (group)?                                                                                               |         |             |
| D4  | `s2-noap.pdf`: are the measurements drawn at all? With a value/caption? Any repair prompt when closing?                                                                                 |         |             |
| D5  | `s2-vp-only.pdf`: with the viewer's **distance tool**, measure the building's long side (outside Detail A). Does it show **20.00 m** without setting a scale (page viewport used)?      |         |             |
| D6  | `s2-vp-only.pdf`: measure the plate's long side **inside Detail A**. Does it show **400 mm** (Detail A 1:5 used)?                                                                       |         |             |
| D7  | `s2-vp-only.pdf`: measure from the building corner into Detail A. Which scale does the viewer use? Any warning?                                                                         |         |             |
| D8  | `s2-cap.pdf`: move one measurement's end point and save. Run `node spikes/s2-measure/read-measure.ts <saved.pdf>`: is `/Measure` kept, and does our value match the viewer's new value? |         |             |
| D9  | `s2-cap-edited-by-embedpdf.pdf`: same as D1. Our later edit must not have removed the measurement data.                                                                                 |         |             |

### F. Reverse direction (their measurements, our reader)

1. Open `s2-vp-only.pdf` in each viewer. Using the viewer's own scale settings where needed (1:100
   in metres), draw one **distance**, one **perimeter** and one **area** measurement on the
   building, and the same three on the plate inside Detail A. Save.
2. Run `node spikes/s2-measure/read-measure.ts <saved.pdf>` (or send the file back to the agent).
   For each measurement it prints our recomputed value, the viewer's displayed value
   (`/Contents`), and the viewport our §7.4 rule picks.
3. Record whether our values match the viewer's to display precision.
