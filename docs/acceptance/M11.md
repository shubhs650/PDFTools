## 4. Found and fixed during M11-09

- **The annotation-load perf gate failed on some CI machines every time** (issue #59; twice in a
  row on PR #133). It compared tile p95 while 10,000 annotations load with a baseline run (+25 %
  - 10 ms). On a busy 4-core runner the Work worker parsing those annotations competes for the
    CPU, so tiles slowed (p95 28 → 112 ms) although the load never touched the Render queue. Worse,
    the timing gate could not catch the regression it was written for: with the load forced back
    onto the Render queue, it **passed** locally (p95 90.6 against a limit of 113.6). The gate now
    checks the route itself: every executor call to the Render worker is counted per method
    (`renderCallCounts` in `src/engine/hostedEngine.ts`, a map increment), and the test requires
    **no `getAnnotationsBatch` call** on the Render worker, neither the plugin's load at open nor the
    one run while scrolling. Forced back onto the Render queue, it fails (8 calls). The tile timing
    stays recorded and is gated only against gross slowdowns (`2 × baseline + 150 ms`). A unit test
    covers the counter both ways (`tests/engine/hosted-engine.test.ts`).

## 5. Known limits carried forward

- **Fonts:** only the fonts that ship with the app (D-52); fonts installed on the computer are not
  supported (D-54 withdrawn). New families may be added later when users ask for them.
- **Form fields** keep the three standard fonts (Q3); fonts for forms are a later task.
- **The tab hover card** says where a file came from, not its folder: a web app cannot know a
  file's path.
- **Pick up where you left off** and Recent need Chrome or Edge on a computer (file handles);
  browsers usually ask once per file after they restart.
- **Small files** show their size as Intl's short form, such as "848 byte"; real drawings are in
  kB or MB.
- **Install budget:** see section 3 (a reference only since 2026-11-07).
- The M10 and M7 limits are unchanged ([M10 acceptance](M10.md) §5, [M7 acceptance](M7.md) §4).
