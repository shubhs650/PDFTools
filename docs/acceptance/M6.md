Found and fixed during M6-15:

- **Bookmark colours could be unreadable** (WCAG AA, rule 12). A bookmark keeps the file's own
  colour (M6-11), and pure red on white is 4.0:1, under the 4.5:1 minimum (worse on the selected
  row's blue). The pane now shows the file's colour when it is readable on every row background
  and otherwise mixes it toward the theme's text colour only as far as needed
  (`src/features/bookmarks/readableColor.ts`, unit-tested); the file's `/C` is never changed.
- **Sign Document's font names were unreadable in the dark theme**: grey text on the white rows
  that preview the ink. They now use the page text colour.
- **Settings → Data on this device** did not mention the comment tool defaults, saved comment
  styles and saved visual signatures that M6-03, M6-07 and M6-13 added (the Privacy page did);
  the note and the Clear all local data confirmation now do.
- **Flaky keyboard menu test** (`e2e/context-menus.spec.ts:193`, failed on `main` after M6-14):
  the arrows were pressed before the menu had focused its first item; the test now waits for it.

## 3. Known limits carried forward (for the interop run and beta users)

- **Forms (M6-14):** joining radio buttons and deleting a widget leave empty fields in
  `/AcroForm /Fields` (checked by P12); `shareField` and staged `/TU`, `/DV`, `/Tabs` changes are
  not undoable; a radio button's export value is its id (Choice1, …).
- **Comment rotation and vertical alignment** are EmbedPDF-private keys (`/EPDFRotate`,
  `/EPDF:VerticalAlignment`); the pictures are standard, but another viewer that regenerates the
  appearance may drop them (P3, P4, Q2).
- **Passwords (M6-12):** with an open password only, it is also the owner password, so whoever
  opens the file can change or remove its security; "Changing the document" implies page changes.
- **Signatures (M6-13):** visual only, not certificate-based (Rev 1 item 3).
- **Rapid moves (M6-10 note):** five quick arrow-key nudges on one comment sometimes saved four
  (EmbedPDF's commit batching). Not reproduced or worked around in M6-15; it stays an open issue
  in `docs/PROGRESS.md` for a fix task.
- The M3/M4 open items (first-open perf task at the limit, ADR-016 d7 leftovers) are unchanged.
