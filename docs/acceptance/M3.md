**UI responsiveness — not clean in this container.** Three full perf runs each had one or two
one-off main-thread stalls, each in a different scenario: run 1 `snap` (121 ms), run 2 M2's
`indexing` (103 ms), run 3 M3-09's `ink` (331 ms) and M2's `print` (169 ms). Every one of these

~2.6 during the runs); this matches the "Perf noise to watch" and "CI perf stalls" open issues.
The table above is run 2. The owner's machine (and CI) decide; if a scenario fails there
repeatedly, it is a bug to fix, not noise.

Found and fixed during M3-16 … M3-20:

- **EmbedPDF's reader drops `/IT` on lines and polygons**, so a saved measurement came back as a
  plain line: the Work worker restores it when listing annotations.
- **A selected group has no vertex handles** in the annotation plugin: selecting a measurement's
  grouped label selects the measurement alone, so its vertices stay editable.
- **Derived edits were separate undo steps**: a measurement's value and label now join the edit's
  step (`historyJoin.ts`, a hook on the history plugin instance, as `authoring.ts` does).
- **ft-in scales lost their fraction** in `/Measure`: now written as Acrobat does (feet, then
  inches with `/F /F`).
- **`workClient.run` ignored a signal aborted before the call**, and a reused submit button re-ran
  the CRS export after Cancel.

## 3. Decisions and open items carried into M4

- **ADR-007 decisions 2 and 3** (measurement labels, viewport semantics for viewer-made files) are
  still the defaults (M3-Q2): the grouped FreeText label is one switch (`LABEL.freeText` in
  `src/model/measurement.ts`). The owner's interop run (§D/§F and §M3 L/M) decides.
- **Snapshots in the CRS** use PDFium's annotation flag (`renderBand`), not the ADR-014 annotation
  tiles ADR-015 d3 proposed: 1,000 rows take ~8 s here; on markup-dense sheets the tile route would
  be faster (a follow-up if the owner's CRS runs are slow).
- **Keyboard text selection** (M2-04) is still an open owner decision; keyboard creation of shapes
  and measurements stays pointer-only (M3-Q6).
- **EmbedPDF internals**: the history join and the author fix patch plugin instances (pinned 2.15.1);
  re-check both on any EmbedPDF upgrade (they fail loudly in the unit and e2e tests).
