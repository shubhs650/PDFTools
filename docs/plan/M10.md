## Design direction (D-47)

One visual language, applied through the existing tokens (`src/ui/tokens.css`; components already
use only tokens, and `tests/ui/tokens.test.ts` and `themeContrast.test.ts` enforce it), so the
change is mostly token values and component CSS. The **layout does not change**: the same top
bar, ribbon, tab strip, left rail and panes, Properties pane and status bar, in the same places
and sizes (± a few px of padding).

1. **Colour.** Cool **slate** neutrals instead of flat greys, and one brighter **blue** brand
   (Q1). Light: app background slate-100 `#f1f5f9`, surfaces white, borders slate-200, text
   slate-900, muted slate-600; brand `#2563eb` (white text 5.2 : 1). Dark: background `#0b1120`,
   surfaces slate-900 `#0f172a`, raised slate-800, borders slate-800/600; **filled** brand stays
   `#2563eb` (white 5.2 : 1) and **accent/lines/links** use blue-400 `#60a5fa` (7 : 1). Every text
   and UI pair is tested at AA (text 4.5 : 1, control boundaries and focus 3 : 1).
   **Unchanged on purpose:** PDF pages stay white; highlight and sticky-note defaults stay yellow;
   comment colours come from the standard swatch picker; Windows High Contrast (`forced-colors`)
   still hands every colour to the system.
2. **Shape.** Radius 6 px for controls, 8 px for menus and cards, 12 px for dialogs and the start
   card. Softer, layered shadows (three elevation levels, tuned per theme).
3. **State.** Hover and pressed are soft tints with eased transitions. A **pressed toggle** is a
   borderless brand tint with brand-coloured icon and text and the Filled icon (ADR-010), so the
   state never relies on the tint alone (WCAG 1.4.11). Focus is a 2 px brand ring plus a soft
   3 px halo, on `:focus-visible` only.
4. **Type.** The same system fonts (rule 4: nothing fetched). Clearer hierarchy: semibold section
   titles, 11 px semibold group labels with a little letter-spacing, muted secondary text.
5. **Motion (new).** Short and calm: 120 ms for hover and press, 180 ms for menus, tooltips and
   panes, 240 ms for dialogs and the backstage, with a standard ease-out curve. Rules:
   - only `opacity` and `transform` animate (no layout, no `filter` or `box-shadow` animation on
     large areas), so animation runs on the compositor and adds **no main-thread long tasks**
     (rule 1; checked by a perf spec);
   - **nothing animates** in the document view: pages, zoom, scrolling, comments being drawn or
     dragged, and the measure tools stay instant;
   - `prefers-reduced-motion: reduce` turns every animation and transition off (tokens go to
     0 ms, already wired in `tokens.css`); `forced-colors` is unaffected;
   - nothing waits on an animation: focus moves and keyboard shortcuts work at once, and e2e
     tests stay stable (Playwright waits for stable elements; animations are disabled in tests
     that measure positions).

A **rough, CSS-only preview** of directions 1–3 (token values and a few rules injected into the
current build, not the final design) is in the shared folder `m10-plan/preview/`, light and dark.

**How the newly accepted items are built:**

- **O3 one-row header.** The product mark, Quick Access (Open, Save, Print, Undo, Redo), File,
  the nine tabs and the right-hand top-bar buttons share one row; the ribbon panel sits directly
  under it, 28 px higher than today. Accessible names, the roving toolbar and keyboard paths stay
  the same. When the row is too narrow (1280 px with the pseudo-locale's +40 % labels), the tab
  list scrolls inside itself, as it does today, and never pushes the top-bar buttons off screen.
  Help screenshots and every e2e locator that relies on the old banner are updated.
- **O4 Create Blank PDF.** **File → New** (and the start screen's quick action; Ctrl+N where the
  browser allows it, as in the installed app) asks for page size (A4, A3, Letter, Legal, custom),
  orientation and number of pages, builds the PDF **in the Work worker** (rule 1) with the
  `FPDF_CreateNewDocument` route that Merge already uses (`src/workers/work/assemble.ts`), and
  opens it as an unsaved tab ("Untitled 1.pdf"); its first Ctrl+S is a Save As. Organize's
  existing **Insert Blank Page** is unchanged.
- **O7 accent colour.** Settings → Appearance gets **Accent: Blue (default), Teal, Indigo,
  Graphite**, each a full set of brand/accent/selected/focus tokens for light and dark, all in
  `themeContrast.test.ts`; stored on the device next to the theme (`pdftools.accent`), applied
  before first paint by `theme-boot.js`, listed on the Privacy page and cleared by "Clear all local
  data". Comment colours, highlight and sticky-note yellow and white pages never follow the accent.
- **O8 Inter.** Inter (OFL-1.1, the variable font, Latin and Latin-extended subsets, about
  100–300 KB as WOFF2) is bundled and served from our origin (`font-src 'self'`, rule 4), in the
  **core** precache so the UI never flashes in another font; the system fonts stay as fallback.
  The license check covers the package; the adaptive ribbon is re-checked because Inter is wider
  than Segoe UI, which is why this task comes before the ribbon task.
- **O9 density.** Settings → Appearance and View → **Density: Comfortable (default) / Compact**.
  Compact reduces padding and row heights in panes, lists, menus and dialogs and tightens the
  ribbon's groups; target sizes never go below 24 × 24 px (WCAG 2.2 SC 2.5.8). Stored on the
  device like the theme.

## Risks

- **Adaptive ribbon fit (D-36).** New padding can push a tab over 1280 px. Mitigation: the
  adaptive-ribbon e2e checks every tab at 1280 px in each PR; spacing changes are budgeted.
- **Tests that read colours or positions.** A few e2e tests check computed colours or element
  boxes. Mitigation: run the full suite (`full-e2e` label) on M10-02, M10-04 and M10-07.
- **One-row header (O3) and Inter (O8) at 1280 px.** Both take horizontal room; the tab list
  scrolls inside its row and the adaptive ribbon steps down, both checked at 1280 px with the
  pseudo-locale in their PRs.
- **More appearance settings (O7, O9).** Four accents × two themes × two densities: contrast is
  tested per accent and theme; density is checked by the adaptive-ribbon spec and axe in both.
- **Help screenshots drift.** All 51 change; regenerated once in M10-09, not in every PR.
- **Contrast regressions in dark.** Every pair is in `themeContrast.test.ts`; the report's own
  dark values fail AA (R12), which is why we do not copy them as they are.
- **Animation cost.** Compositor-only properties, no animation in the document view, and a perf
  spec for the animated surfaces.
