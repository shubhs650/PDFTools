**Why this order.** Spikes first where library behavior is unmeasured and the design is at risk:
page operations touch the save tracker, recovery, the Work-worker refresh and every page-indexed
cache (and decide M4-Q1's undo route); redaction must meet rule 8 on top of an engine we have not
used yet, and its verification algorithm is the riskiest piece of M4. Oxide and the shared export

operations follow their spike; reorder and multi-file operations reuse the core. Tables are
pure-logic first (TDD), then the one-click path, then the review UI and templates. Redaction is

dependency and **runs early, next to M4-01 and M4-02** (it may share M4-01's reopen route), while

## M4-01 — Spike: page operations, save, undo and cache invalidation (ADR-016)

> **Status (2026-09-29):** done — _works with workaround_,
> [ADR-016](../adr/016-m4-page-operations.md) (proposed; decisions 3, 5, 7 need the owner). Spike
> `spikes/s14-pages/` (Node: 40-case save matrix on 5 original forms, all qpdf-clean and identical
> after reopen). Semantic dirty set: 0.3–4.8 KB tails vs 2.6–12.7 KB keep-all (2,000-page stand-in:
> 0.24 MB vs 1.82 MB). Found: EmbedPDF's page cache is keyed by index (stale after an operation);
> the core reducer handles no page-list refresh and the annotation plugin drops annotations that
> change page on reload (workaround: empty the store first); ADR-005's check cannot see page order
> (negative control passes); deleted pages leave dangling dests and orphaned fields; a keep-all save
> makes the Signatures pane list a signature twice (existing bug). Undo by reopen: 0.5 s on 2,000
> pages (Node).

**Goal.** Prove how rotate, delete, insert blank, insert from file, move and extract work through
PDFium in our two-worker model, how they save with the narrow Ctrl+S, and how undo and every
page-indexed cache follow them. Record the result as ADR-016 (works / workaround / blocker).

**Refs.** D-06, D-09, D-10, §3.1, §4.2, §4.3, §7.8, ADR-001 B11/B14, ADR-004, ADR-005, ADR-012,
ADR-014, M4-Q1, M4-Q8, rules 1, 2, 7, 9.

**Depends on.** — (answers feed M4-Q1 and M4-Q8).

**Files likely touched.** `spikes/s14-pages/` (harness, Node + browser, project `s14`),
`docs/adr/016-m4-page-operations.md`, `playwright.config.ts` (spike project), `docs/PROGRESS.md`.

**Acceptance criteria.**

- Which API does each operation: EmbedPDF 2.15.1 engine methods if they exist, else direct
  exports (B14): `FPDFPage_SetRotation`, `FPDFPage_Delete`, `FPDFPage_New`,
  `FPDF_ImportPagesByIndex`, `FPDF_MovePages`; each listed in the ADR.
- **Save:** after each operation (alone and mixed with annotation edits), Ctrl+S produces one
  narrow revision that qpdf accepts, the Work-worker verification (ADR-005 d2) passes or its
  needed extension is described, and the keep-all fallback still works. Measured: tail size vs
  a full rewrite; xref-table and xref-stream originals; object-stream originals; encrypted (M3-04)
  originals; a signed file (signature becomes "modified after signing", warning text).
- **Dangling references:** what happens to outline destinations, named dests, links and
  `/AcroForm` fields that point at a deleted page; what `ImportPages` carries (annotations,
  widgets, outlines, page labels, `/VP`). Proposal for each (M4-Q8).
- **Undo (M4-Q1):** time to restore by reopening original + pre-operation tail, on the 2,000-page
  stand-in and the A0 sheet; effect on open annotations' undo timeline; memory.
- **Cache invalidation map:** every cache keyed by page index or object number (text cache and
  background index, geometry and Snap-worker indexes, annotation store and `obj-<n>` ids,
  thumbnails, links, comment numbers, scale viewports, recovery snapshot, Work-worker copy) and
  how each is refreshed; no main-thread task > 100 ms while deleting 1,000 of 2,000 pages.
- ADR-016 proposed, with owner decisions marked.

**Tests.** Spike Playwright spec (`SPIKE=s14`) and Node matrix (qpdf check on every output). No
production code.

## M4-02 — Spike: redaction apply, sanitize and verification (ADR-017)

> **Status (2026-09-29):** done — _works with workaround_,
> [ADR-017](../adr/017-m4-redaction.md) (proposed; decisions 3 and 5 need the owner, 3 amends B8's
> wording). Spike `spikes/s15-redaction/` (Node). `EPDFPage_ApplyRedactions` removes text of every
> kind (invisible, white, rotated, offset, hidden layer, inside forms), image pixels and paths wholly
> inside; it leaves **paths crossing a rectangle** (78 on the A0 sheet), all other annotations and
> all document-level data. A prototype that re-cuts crossing paths through PDFium's page-object API
> plus an object-layer sanitize and a second PDFium rewrite passes the location check, the string
> rule and a canary scan on 8 of 9 adversarial pages; page 9 (a crossing path inside a Form
> XObject) fails verification loudly, as rule 8 wants. AES-256 output stays encrypted. 200 pages ×
> 600 marks: capture 0.5–0.7 s, apply 0.8–0.9 s, verify 0.4–0.5 s (Node). `plugin-redaction`
> (MIT) marks and lists; its commit edits the open document, so Apply is ours.

**Goal.** Measure `@embedpdf/plugin-redaction` / engine redaction on text, images and vector
content, design the sanitize step and the location-based verification, and record them as
ADR-017.

**Refs.** D-31, §7.9, ADR-001 B3/B8/B14, ADR-005 d3, ADR-013 (copy with unsaved edits), M3-04,
M4-Q3, M4-Q4, rules 1, 2, 5, 8, 9, 13.

**Depends on.** — (answers feed M4-Q3 and M4-Q4).

**Files likely touched.** `spikes/s15-redaction/` (self-made adversarial fixtures, harness),
`docs/adr/017-m4-redaction.md`, `package.json` (spike: `--no-save` install only, as S13 did),
`docs/PROGRESS.md`.

**Acceptance criteria.**

- License gate result for `@embedpdf/plugin-redaction` 2.15.1 (MIT, deps `@embedpdf/utils`,
  `@embedpdf/models`).
- Behavior on self-made fixtures: text fully/partly inside a rect, text under an image, white or
  invisible (render mode 3) text, text in a Form XObject, inline images, image partly inside
  (pixels blacked or image dropped?), vector paths crossing the rect, rotated and crop-offset
  pages, `/Redact` annotations from other viewers (`/OverlayText`, `/IC`).
- Where Apply runs (Work-worker copy with unsaved edits is the default) and the full-rewrite route
  (`FPDF_NO_INCREMENTAL` through our writer), including encrypted sources (M4-Q4).
- **Sanitize list** with the API for each: Info dictionary, XMP `/Metadata`, `/Thumb`, annotations,
  widgets/form values, links and outline items intersecting redacted areas, `/Redact` annots
  removed after apply; what else a redacted file can leak (JavaScript, embedded files, page
  piece info, `/StructTreeRoot` alt text, `/AcroForm` field values) and a proposal for each.
- **Verification algorithm** (B3), timed: text (`FPDFText` char boxes), page objects by type
  (`FPDFPage_CountObjects`, bounds, path segments, image bitmaps via `FPDFImageObj_GetBitmap`
  mapped into image space), Form XObjects recursively, plus the string search rule; a planted leak
  of each kind is detected (negative controls).
- Time for apply + rewrite + verify on a 200-page contract with 500 marks and on the A0 sheet.
- ADR-017 proposed.

**Tests.** Spike Playwright spec (`SPIKE=s15`) and Node harness; every negative control must fail
verification.
