## Workflow (every task)

1. One task = one project thread = one branch = one PR, done **serially** in the order below.
2. The thread reads CLAUDE.md, this plan's task, ADR-023 and the ARCHITECTURE.md sections cited.
3. Bugs first get a failing e2e that reproduces them as a user would (pointer and keyboard, no
   test-hook shortcuts for the step under test), then the fix.
4. Code + tests; the CLAUDE.md "done" checks: `typecheck`, `lint`, `format:check`, unit tests,
   the relevant e2e (Playwright, `PW_CHROMIUM_EXECUTABLE=/opt/pw-browsers/chromium` in the cloud
   container), `licenses`, no new main-thread long task (> 100 ms).
5. UI tasks attach Playwright screenshots at 1280 × 800 and 1920 × 1080 to the PR (light and,
   from M7-11 on, dark) and copy them to project files `m7-xx/`.
6. PR → **green CI** → **squash merge**. `docs/PROGRESS.md` updated in the same PR; commits cite
   ADR-023 and the D-xx ids. Minor perf-check flakes go on issue #59 and do not block a PR.
7. The deployed beta (Cloudflare) picks up `main` after each merge; the owner spot-checks there.

### M7-02 — Text comments: create and edit without losing text (B1, B2, B3)

**Goal.** Review 4b-i and 4b-iii — the two Critical bugs.

**Refs.** ADR-023 D-43; D-03; rules 1, 6, 11, 12; §7.1.

**Scope.**

- **New text comment starts editing.** After Text Box, Typewriter or Callout creates its comment
  (drag or click), it is selected and its editor opens with **"Type here" selected**, so the
  first key replaces it (PDF-XChange behaviour). The placeholder is the tool's
  `defaults.contents` (so the plugin's "is default content" check selects it), not only
  `clickBehavior.defaultContent`.
- **One commit path.** The edit is committed on every way out of the editor: Esc, a click
  elsewhere on the page or in the panes, a tool change, a tab change, Ctrl+S, closing the
  document. Esc while editing first commits and leaves edit mode (the comment stays selected); a
  second Esc deselects. The commit is one undo step. Implemented as our wrapper around the
  plugin's free-text editor (or a patch target in `drawTools.ts`), not by forking the plugin.
- **Callout commit.** The callout's editor goes through the same commit path (B2); the page
  tile is re-rendered from the committed text, so the page never shows the old text.
- Empty text after editing: the comment keeps its rect and an empty `/Contents` (not deleted),
  as PDF-XChange does; Undo restores the text.
- Appearances stay PDFium's (regenerated after the commit); nothing app-private is written.

**Files.** `src/features/annotate/tools/drawTools.ts`, `src/features/annotate/AnnotationLayer.tsx`
(free-text renderer wrapper), `src/features/annotate/selection.ts`, `src/app/keys/keymap.ts`
(`tool.cancel` while editing), `src/features/annotate/AnnotationTileLayer.tsx` (tile refresh).

**Acceptance.** For each of the three tools, with the mouse and with the keyboard (T, Enter): create
→ type "Hello" → the contents are "Hello" (not "Type hereHello"); edit to "Hello world" → Esc →
the page shows "Hello world" and the saved file has `/Contents (Hello world)`; the same with a
click elsewhere and with a tool change; reselect → Esc shows "Hello world"; one undo step per
edit; no long task.

**Tests.** E2E (reproduce first): `e2e/text-comments.spec.ts` — the review's exact steps for each
tool, Esc / click-away / tool change / Ctrl+S, saved-file readback, undo. Unit: the commit helper.

### M7-03 — Text comments: select, move, callout box (B4, B5, B6, B11)

**Goal.** Review 4b-iv and 4b-v (first two bullets).

**Refs.** ADR-023 D-43; D-38 (a); rules 9, 12; §7.1.

**Scope.**

- **One click** on any part of a text box, typewriter or callout (its box, its text, a callout's
  leader line) selects it; dragging the body **moves** it (callout: the box and line together;
  the arrow tip keeps its own handle); handles resize; Delete deletes; the context menu (M6-02)
  works on it. The pointer shows `move` over a selected text comment.
- **Double-click** enters edit mode at the clicked character (Enter or F2 does the same from the
  keyboard on a selected text comment); inside the editor, a click places the caret and a drag
  selects text — it does not move the comment.
- Focus: leaving edit mode returns focus to the document view, so Delete, Ctrl+C/X/V and the
  arrow keys act on the comment again (B6).
- **Callout by drag (B11):** press on the arrow tip and drag to where the box goes; the knee is
  placed automatically (PDF-XChange gesture). The three-click route keeps working. The status bar
  hint says "Drag from the point to the text box position".
- Locked comments (M6-06) still neither move nor edit; read-only without annotate permission
  (rule 9).

**Files.** `src/features/annotate/AnnotationLayer.tsx`, `src/features/annotate/tools/drawTools.ts`
(callout pointer handler wrapper), `src/features/annotate/selection.ts`, `src/i18n/en.json`.

**Acceptance.** Text box, typewriter and callout: click the box → selected; drag → the saved
`/Rect` (and callout `/CL`) moved by the drag; Delete removes, Ctrl+Z restores; double-click →
caret in the text; drag inside the editor selects text; a callout made by one drag has an arrow,
a knee and a box; locked and permission-restricted files refuse moves.

**Tests.** E2E: `e2e/text-comments.spec.ts` (selection and move part), the callout drag, locked
and restricted files. Unit: the callout knee placement.

### M7-04 — Comment selection: marquee, Shift+click, select after drawing (B7, B8, B9, B13, B14)

**Goal.** Review 4a and the remaining selection bugs from 4f.

**Refs.** ADR-023 D-43 and the D-36 amendment; rules 1, 12; §7.1.

**Scope.**

- **Marquee:** with Select Comments, a drag that starts on empty page space draws a selection
  rectangle and selects every comment it touches (the plugin's marquee — `enableMarquee: true`
  for the pointer mode — with our selection outline and group box as in the review's
  screenshot: one bounding box with handles around the whole selection, each member outlined).
  With **Select**, a drag on empty space that starts over no text also marquee-selects comments;
  a drag that starts over text selects text, as now.
- **Shift+click** adds or removes a comment (as Ctrl+click); Ctrl+A with Select Comments selects
  every comment on the page; Esc clears.
- The selected group moves, nudges (arrow keys), deletes, copies, flattens and restyles as one
  undo step.
- **After drawing (B9):** the new comment is selected (handles shown, Properties pane follows);
  the tool stays on as today, and the next press on empty space starts
  a new comment.
- **B13:** queued moves are applied in order so the last nudge of a rapid series is never lost
  (the M6-10 note).
- **B14:** compare with PDF-XChange (owner note in the PR); fix only if ours differs.

**Files.** `src/features/view/plugins.ts` (selection plugin modes), `src/features/annotate/selection.ts`,
`src/features/annotate/AnnotationLayer.tsx`, `src/features/select/commands.ts`, `src/app/app.css`.

**Acceptance.** Marquee selects exactly the comments it touches on that page (not text, not
form fields); Shift+click toggles; a group drag moves every member by the same offset, saved;
ten quick nudges end where ten slow ones do; a new rectangle is selected right after it is drawn;
1,000 comments on a page: marquee stays smooth (no long task).

**Tests.** E2E: `e2e/comment-selection.spec.ts`; perf: a marquee over 1,000 comments. Unit:
hit-test of the marquee rect against rotated pages.

### M7-05 — Right-click menu inside text comments (B10)

### M7-06 — Sticky note popup (B12)

### M7-08 — Paste an image onto the page

**Goal.** Review 4e.

**Refs.** ADR-023 D-45; D-23 (image stamps); rules 1, 9, 11; §7.1, §7.3.

**Scope.**

- **Ctrl+V** with an image (PNG, JPEG; also a GIF/WebP/BMP converted to PNG in the Encoder
  worker) on the system clipboard pastes it on the current page, centred in the visible part
  of the page. **Right-click → Paste** on the page background pastes it centred at the pointer.
  When both our comment clipboard (ADR-018) and an image are available, the most recent copy
  wins (a timestamp kept with our clipboard).
- **Size:** the image keeps its aspect ratio and is scaled down so it fits inside the page with a
  margin (90 % of the page's width and height), never scaled up beyond its own size at 96 dpi;
  placed fully on the page (moved in from the edges if needed).
- Written as an **Image Stamp** (standard `/Stamp` with an image appearance, M3-14's path), one
  undo step, selected after pasting; the 20 MB image-stamp cap applies with a message; needs the
  **annotate** permission (rule 9).
- Clipboard access: the Ctrl+V path reads the `paste` event's data (no permission prompt); the
  menu path uses `navigator.clipboard.read()` on the click, which Chrome may ask the user to allow
  once — the menu explains if it is refused. Nothing is uploaded (rule 4).

**Files.** `src/features/annotate/transfer/copyPaste.ts`, `src/features/stamps/imageStamp.ts`,
`src/model/stamp.ts` (`fitWithin` for the page), `src/features/select/commands.ts`,
`src/workers/encoder.worker.ts` (format conversion), `src/i18n/en.json`.

**Acceptance.** A 4000 × 3000 screenshot on the clipboard pastes onto an A4 page inside its
margins with the right aspect ratio; a small icon pastes at its own size; at the pointer from the
menu; saved and reopened as a Stamp with an image; refused with a reason on a no-annotate file;
no long task while decoding a large image (decode off the main thread).

**Tests.** Unit: fit-to-page math. E2E: `e2e/paste-image.spec.ts` (Ctrl+V and menu, sizes,
permission, readback), offline (no request).
