## What we found

### Deployment today

- `main` deploys the beta Worker **`pdftools`** (`pdftools.shubhampatil650.workers.dev`) through
  Cloudflare **Workers Builds** (Git-connected; `npx wrangler deploy`), and every PR gets a
  preview URL (`npx wrangler preview`). `wrangler.jsonc` has one Worker, no custom domain.
- GitHub Actions only runs CI (`.github/workflows/ci.yml`); nothing deploys from Actions and no
  tags exist. `package.json` says `0.10.0-beta`; File › About shows that plus the commit.
- ARCHITECTURE.md D-28 still names `pdf-tools.openengtools.com`, and
  `docs/deploy/cloudflare-pages.md` describes the old Pages setup.

### About, What's new and the home button

- About (`src/app/about/About.tsx`) shows version, commit, build date and offline state, and has
  Copy version info, Help, Report an issue (GitHub new-issue page) and Privacy. There is **no
  link to the repository itself**.
- What's new (`src/i18n/whatsnew.en.json`) has 7 beta releases (`beta-m6` … `beta-m11-fixes`).
- The home button is `app.home` (D-35): `TopBar.tsx`, `commands.ts`, `commands/builtins.ts`,
  `links.ts` (`OPENENGTOOLS_URL`), two i18n strings, the Privacy text that mentions it, one Help
  paragraph, and `e2e/theme.spec.ts`. It also shows in the Help screenshots of the whole window.

### References to the other editor

- **227 lines in 70 files** mention it: 28 source files (code comments; two Help sentences such
  naming it next to Acrobat Reader as a viewer that shows our comments), CLAUDE.md (rules 5 and
  15, the opening line), ARCHITECTURE.md (11), README, 10 ADRs, 11 plans, 8 acceptance files,
  PROGRESS, 4 release notes, the interop CHECKLIST (26), e2e and spike test names. No file name,
  icon or image in the app carries it.
- **`docs/ui-reference/`**: 6 screenshots of that editor's ribbon (6.6 MB). These are the
  riskiest files: they are its artwork.
- **`corpus/`**: 7 third-party PDFs (32 MB: practice drawings from a CAD vendor, a motor
  catalogue, a bearing catalogue, a journal article, …) plus `manifest.json` and README. Only
  `tests/objects/reader.test.ts` reads it, and only if the folder exists; `npm run corpus` and
  `scripts/fetch-corpus.ts` go with it.
- **Git history:** removing files and words from the tree leaves them in every earlier commit of
  this **public** repository, and in the 138 pull requests' refs, which GitHub keeps even after a
  history rewrite (only GitHub Support can purge those). See Q5.

## The plan

Each task is its own PR, in this order, with green CI and a squash merge.

### V1-01 — Remove the other editor's name and the reference material

- Delete `corpus/` and `docs/ui-reference/`; remove `npm run corpus`, `scripts/fetch-corpus.ts`,
  the `corpus` entry in the reader test, and the ignore lines that name them.
- Reword every mention in code comments, Help text, tests, spikes and docs to neutral wording
  ("desktop PDF editors", "other PDF viewers", "Acrobat Reader and other viewers"), keeping the
  meaning. Interop steps in the CHECKLIST become "a second desktop PDF editor".
- CLAUDE.md: rules 5 and 15 keep their protection without the name ("never copy code, icons or
  artwork from other PDF products").
- ARCHITECTURE.md: same rewording under ADR-029 (Rev 0.19).
- **New CI guard:** a unit test that fails if the name comes back anywhere in the tracked files
  (case-insensitive, all spellings), so it cannot slip in again.

### V1-02 — Top bar, About and What's new for 1.0.0

- Remove the home button (`app.home`, `OPENENGTOOLS_URL`, its strings, its Privacy and Help
  mentions); D-35 updated.
- `package.json` version **1.0.0** (About then shows `1.0.0` and the commit).
- About: a new **Source code on GitHub** button that opens the repository in a new tab (a user
  navigation like Report an issue; the app makes no request, rule 4).
- What's new: **one entry, "Version 1.0.0, the first public release"**, with 4–5 short
  highlights of what the app does. The seven beta entries leave the app (their notes stay in
  `docs/release-notes/`). Users of the new domains have never seen a beta, so a beta history
  means nothing to them; one entry also gives About a clear "what is this release". Reason it
  isn't blank: an empty What's new looks broken. If you prefer it blank, I hide the section.
- Help: regenerate the screenshots (`npm run help:screenshots`), since the top bar changes.

### V1-03 — Deploy from a tag

- `wrangler.jsonc` gains a **production environment**: its own Worker (proposed name
  `triya-pdf`) with the two domains as **Custom Domains** and no `workers.dev` URL. The beta
  Worker `pdftools` is untouched, so pushes to `main` can never reach the release domains.
- New `.github/workflows/release.yml`, run by pushing a tag **`v1.0.0`** (pattern `v*.*.*`), or
  by Run workflow with a tag name (to redeploy or roll back to an older tag):
  1. checks the tag matches `package.json`'s version and its commit is on `main`;
  2. runs the CI checks (typecheck, lint, format, unit tests, licenses, build, dist checks);
  3. deploys `dist/` with wrangler to the `triya-pdf` Worker (wrangler runs only in CI, as
     today; it is still not a dependency, ADR-003);
  4. creates a **GitHub Release** for the tag with `docs/release-notes/v1.0.0.md`.
- Optional approval gate: a GitHub **environment** `production` with you as required reviewer,
  so a tag waits for one click before going live.
- `docs/deploy/release.md`: your one-time setup (domains on Cloudflare, an API token, two GitHub
  secrets, the per-host settings that keep Cloudflare from injecting scripts), how to release
  and how to roll back. The old Pages doc is marked superseded. D-28 updated.

### V1-04 — README

A front page like popular open-source projects: logo, name and one-line pitch, badges (licence,
CI, version), **Open the app** links to both domains, a light and dark hero screenshot, a short
"why" (free, offline, private, made for engineering drawings), features in groups with 4–6
screenshots (measure with scale, comments, redaction, forms, organise pages, OCR), privacy and
offline in plain words, install as an app (PWA), supported browsers, keyboard and accessibility,
built with, development commands, contributing, licence. Screenshots come from the e2e build
with self-made PDFs only (rule 13), via `e2e/support/shots.ts`, stored in `docs/images/`. Also a
short `CONTRIBUTING.md` and a bug-report issue form that reminds people never to attach
confidential PDFs.

## Questions

- **Q1. Domains on Cloudflare.** Custom Domains need both zones in the **same Cloudflare
  account** as the Worker. Is `openengtools.com` already a Cloudflare zone in that account? Has
  `triyapdf.com` been added to Cloudflare (its nameservers changed at the registrar)? Both are
  dashboard and registrar steps only you can do; the deploy doc will list them.
- **Q2. Two domains, two apps.** Each domain is a separate origin: installing the app, Settings,
  recent files, recovery and What's new are kept per domain, so a user who uses both sees two
  different apps. Options: **(a)** both serve the app, as you said; **(b)** `app.triyapdf.com`
  serves the app and `triya-pdf.openengtools.com` permanently redirects to it (one Cloudflare
  redirect rule, both links keep working). **Recommended: (b)**, one place for users' data. (a)
  works too, and the plan above supports it.
- **Q3. The beta.** Keep `pdftools.shubhampatil650.workers.dev` deploying from `main` as a
  staging site (and PR previews)? **Recommended: yes**, so you can try `main` before tagging.
- **Q4. Tags and approval.** Tags `vMAJOR.MINOR.PATCH` (`v1.0.0`), must match `package.json`,
  from `main` only. Do you want the one-click approval gate before each deploy? **Recommended:
  yes.**
- **Q5. Git history** (the files and the name stay in earlier commits of a public repository):
  - **(a)** leave history as it is: only the current files are clean.
  - **(b)** rewrite history in place (`git filter-repo` to drop the two folders and replace the
    name in every commit, then force-push `main`): all commit hashes change, old links to commits
    break, and the 138 PR refs still hold the old files until GitHub Support purges them.
  - **(c)** start a **fresh public repository** (for example `triya-pdf`) from the cleaned 1.0.0
    tree with one first commit, and make this repository **private** as the full-history archive.
    You create the empty repository and give Claude access; Cloudflare and the GitHub links then
    point to the new one. The cleanest result, and the new name matches the product.
  - **Recommended: (c)**, decided before V1-02, because the About link and the issue link name
    the repository. Nothing here is done without your explicit yes.
- **Q6. What's new:** one "first public release" entry (my choice above), or blank?
- **Q7. Licence holder:** `LICENSE` says "Copyright (c) 2026 shubhs650". Keep, or your full
  name?
