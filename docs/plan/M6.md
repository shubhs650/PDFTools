## Workflow (every task)

1. One task = one project thread = one branch = one PR, done **serially** in the order below.
2. The thread reads CLAUDE.md, this plan's task, ADR-021 and the ARCHITECTURE.md sections cited.
3. Code + tests; the CLAUDE.md "done" checks: `typecheck`, `lint`, `format:check`, unit tests,
   the relevant e2e (Playwright, `PW_CHROMIUM_EXECUTABLE=/opt/pw-browsers/chromium` in the cloud
   container), `licenses`, no new main-thread long task (> 100 ms).
4. UI tasks attach Playwright screenshots at 1280 × 800 and 1920 × 1080 to the PR.
5. PR → **green CI** → **squash merge**. `docs/PROGRESS.md` updated in the same PR; commits cite
   ADR-021 and the D-xx ids.
6. The deployed beta (Cloudflare) picks up `main` after each merge; the owner spot-checks there.

## Tasks

### M6-01 — Top bar, full screen, magnet snapping toggle

**Goal.** A1a–A1d and A3.

**Refs.** ADR-021 D-35; rules 4, 10, 11, 12, 15; §8, §10.2.

**Scope.**

- Banner: product mark (`public/icons/icon.svg`, our own artwork) + "PDFTools" at the left of the
  quick access row; the visual title replaces the screen-reader-only `h1` (kept as the heading).
- Right end of the tab row: **OpenEngTools** (the standard Fluent `Home` icon, owner's choice) → `https://www.openengtools.com`;
  **Report an issue** (Fluent `Bug`) → `https://github.com/shubhs650/PDFTools/issues/new?title=…&body=…`
  with app version, commit, browser, OS only (a pure builder, unit-tested to contain nothing from
  the document store); **Full screen** (Fluent `FullScreenMaximize` / `FullScreenMinimize`) via
  `document.documentElement.requestFullscreen()`; Esc or the button leaves; the ribbon, panes and
  status bar stay (it is the app, not the page, that goes full screen). Keymap: a full-screen
  shortcut (F11 is the browser's own; we bind Ctrl+Shift+F11 and show it in Help).
- Links open with `target="_blank" rel="noopener noreferrer"`; URLs live in one config module.
- Status bar: snapping toggle becomes a magnet icon toggle button (custom 20 px icon drawn in the
  Fluent Regular grid + Filled variant for pressed), tooltip and accessible name "Enable
  snapping"; "Preparing snapping…" stays as text.
- Help → Send Error Report gains a line pointing to the GitHub option; Privacy page mentions that
  the two links open external sites in a new tab and send nothing by themselves.

**Files.** `src/app/AppFrame.tsx`, `src/app/TabStrip.tsx` (or a new `src/app/TopBar.tsx`),
`src/app/links.ts` (new), `src/app/keys/keymap.ts`, `src/features/measure/SnapStatus.tsx`,
`src/ui/icons/custom/magnet*.svg`, `src/app/commands.ts` (`app.home`, `app.reportIssue`,
`view.fullScreen`), `src/i18n/en.json`, `src/features/help/*`.

**Acceptance.** Brand visible at 1280 px without pushing the tabs; the two links open new tabs
(Playwright `context.waitForEvent('page')`) and the app makes **zero** requests (offline e2e still
green); the issue body contains no file name or page text with a document open; full screen
enters/leaves and the layout fills the screen; magnet toggle pressed/unpressed states, keyboard
reachable, axe clean.

**Tests.** Unit: issue URL builder; keymap entry. E2E: links, full screen, magnet toggle, axe.

### M6-02 — Context menus; cut / copy / paste comments on the page (non-negotiable)

  position (page + PDF point); Ctrl+V keeps "same place + 10 pt" (ADR-018).

**Files.** `package.json`, `src/ui/components/ContextMenu.tsx`, `src/features/annotate/AnnotationLayer.tsx`,

### M6-12 — Password security (apply / remove)

**Goal.** C2, per S18's verdict.

**Scope.** Protect → **Password Security…**: open password (+ confirm), permissions password (+
confirm), permission tick boxes, encryption level shown (AES-256); passwords at most 127 UTF-8
bytes (S18); output via **Save As** to a new file with a full rewrite, made on a **copy** (ADR-022
decision 2: rewrite the current state, open it as a second document, set / remove encryption,
rewrite, close — the open document and its Ctrl+S are never touched); verification in the Work worker (opens with each password,
permissions as set, page/annotation counts equal) before success; signed-document warning.
Protect → **Remove Security** and changing passwords only with **owner rights** (unencrypted,
owner password, or owner-unlocked — not just "modify": PDFium removes encryption without them). Passwords never stored or logged; dialog
fields are `autocomplete="new-password"`.

**Acceptance.** Output opens in PDFium with both passwords, refuses without; restricted commands
disabled when reopened with the user password (our D-19 path); owner-run Acrobat / PDF-XChange
check; rule 9: the command is unavailable on a document opened without owner rights.
