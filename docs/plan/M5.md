## What earlier ADRs change for M5

| Source  | M5 consequence                                                                                                                                                                                                                                  |
| ------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| ADR-002 | Two new runtime packages, both permissive (`tesseract.js-core` Apache-2.0; `@tesseract.js-data/eng` MIT, data Apache-2.0); the license gate and the third-party notices cover them automatically. Install budget +6.1 MB raw of the 60 MB (§9). |
| ADR-003 | Same-origin everything: the core's WASM is a hashed asset passed through `locateFile`, the data a file under `/ocr/`; the glue's own URL default is never used. CSP unchanged (`'wasm-unsafe-eval'` already there).                             |
| ADR-004 | A third PDFium-free worker type (OCR). Its WASM memory only grows: started on first use, terminated when the job ends (and for a mid-page cancel). The Work worker renders the raster (never the Render worker, the scroll path).               |
| ADR-005 | The text layer is new objects plus a rewritten page dict: Ctrl+S stays a narrow verified tail (the comment-transfer route proves it).                                                                                                           |
| ADR-013 | Capability **modify** (rule 9): the command is disabled with the usual reason on restricted documents; the Render worker checks it again when applying.                                                                                         |
| ADR-016 | OCR is a page change: one undo step through the snapshot route, every per-page cache dropped (`invalidatePages`), the Work copy synced (`syncLive`) so search, selection, tables and exports see the new text.                                  |
| ADR-018 | `pagesApply` (reopen with objects) carries the text layer; `applyObjects` gains the capability to check; `runTransfer` is reused as the main-thread flow (produce → apply as one step).                                                         |
| ADR-019 | Express Extract's "requires OCR" note stays for pages that were not recognized; recognized pages extract like any text page.                                                                                                                    |

## Explicitly **not** in M5

Languages other than English (the mechanism is ready: one package per language and a picker);
non-Latin characters in the text layer (dropped); orientation detection and deskew; image
preprocessing (binarization thresholds, despeckle); re-recognizing pages that already have text;
an OCR quality/DPI option (300 dpi fixed); a visible-text (editable) output; OCR of images inside
exports; batch OCR of many files.

## Tasks

### M5-01 — S17 spike and ADR-020

> **Status (2026-10-03):** done. `spikes/s17-ocr/` (Node and browser parts),
> [ADR-020](../adr/020-m5-ocr.md). Findings that shaped the design: PDFium's
> `FPDFPage_GenerateContent` rewrites every content stream of the page (rejected); our object
> layer appends an invisible text stream behind a `q`/`Q` wrap and keeps the originals byte for
> byte; the core recognizes a 300 dpi A4 page in ~1 s in a worker under the CSP with no network.

### M5-02 — OCR worker, client, assets, precache

> **Status (2026-10-03):** done. `src/workers/ocr.worker.ts` hosts `tesseract.js-core`'s
> `simd-lstm` build (its WASM a hashed asset through `locateFile`; the English data inflated
> from `/ocr/eng.traineddata.gz` with `DecompressionStream`); `src/engine/ocrApi.ts` and

> Licenses 765 OK. Unit: client lifecycle (3), iterator parsing (3), precache split.

**Goal.** `tesseract.js-core` hosted in our own worker behind the typed RPC, with the English
data self-hosted and precached in the background.

**Refs.** ADR-020 d1, d2, d6; rules 1, 2, 4, 5; §9; §10.1.

**Files.** `package.json` (two dependencies), `scripts/vite-assets.ts` (`ocr/eng.traineddata.gz`),

**Acceptance.** `init` loads the core and the data from this origin only; `recognize` takes a gray

progress; a cancel terminates the worker; the client restarts it lazily; the license gate is
green; the e2e offline proof covers the new files.

**Tests.** Unit: precache split (new entries), the client's lifecycle (terminate after the job,
restart on the next), iterator parsing with a fake module. E2E (M5-04 ships them): zero

### M5-04 — Convert → Recognize Text (OCR)

> **Status (2026-10-03):** done on the agent side. `convert.ocr` (milestone M5, Fluent
> `ScanText`), `src/features/ocr/{commands,ocrJob,OcrDialog}.ts(x)`: the dialog resolves the
> scope and closes; the job runs through `runTransfer` (capability modify), so the
> page-operation busy dialog shows "Page n of m" with Cancel and the result is one undo step;
> the OCR worker is terminated when the job ends; "n pages recognized (w words); m skipped" is

> `e2e/perf/ocr.spec.ts` (20 pages in 20.6 s while scrolling, 0 long tasks); the self-made scanned fixture lives in `e2e/fixtures/scanned.ts`
> (rendered with PDFium at test time).

**Goal.** The command, the dialog and the flow: scope, skip pages with text, progress and Cancel,
one undo step, announcements; search, selection and tables see the text.

**Refs.** ADR-020 d5–d8; rules 2, 9, 11, 12; §6; §7.7.

**Files.** `src/app/commands.ts` (`convert.ocr`, milestone `M5`, `AVAILABLE_MILESTONES`),
`src/features/ocr/{commands.ts,ocrJob.ts,OcrDialog.tsx}`, `src/app/App.tsx`, `src/i18n/en.json`
(`ocr.*`, `command.convert.ocr`, `ribbon.group.convert.ocr`), `src/testing/ocrProbe.ts`,
`e2e/fixtures/scanned.ts` (the S17 fixture, generated at test time with PDFium in Node),
`e2e/ocr.spec.ts`, `e2e/perf/ocr.perf.ts`.

**Acceptance.** Convert → Recognize Text (OCR) on a scanned document: the dialog (pages: all /
current / custom / selection; "Pages that already have text are skipped"), progress "Page n of
m" with Cancel, result line ("n pages recognized, m skipped"); afterwards Quick Find finds a
word on a recognized page and Ctrl+S writes one narrow verified revision; Ctrl+Z removes the
layer; disabled with the reason on a document without the modify permission; works offline with
zero outbound requests; no main-thread task > 100 ms while a 20-page scan is recognized.

**Tests.** E2E: the flow above on the self-made scanned fixture (find, save, undo, denied,
offline, axe on the dialog, keyboard). Perf: 20 scanned pages while scrolling, 0 long tasks.
