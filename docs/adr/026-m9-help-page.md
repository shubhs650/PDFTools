# ADR-026: M9 — Help in its own window, with screenshots

- **Status:** Proposed (2026-11-07)
- **Date:** 2026-11-07
- **Deciders:** owner (Shubham) / agent (M9 thread)
- **Related decisions:** D-17 (offline), D-22 (CSP, no network), D-30 (i18n, accessibility),
  D-42 (dark theme), ADR-002 (licenses), ADR-003 (precache split); ARCHITECTURE.md §8, §9
- **Related milestone:** M9 ([plan](../plan/M9.md))

## Context

Help → Help is a modal dialog with 22 text-only paragraphs (M2-17, extended in M6-15 and M7-12).
The owner asked (2026-11-07) for "a proper separate help page instead of floating help window",
with screenshots, and answered the planning questions: a separate window, offline, rewritten
step-by-step text, and the dialog removed. The owner also said the 60 MB install budget (§9) is a
reference, not a strict limit. The app measures 57.6 MB today, and the screenshots add about
2 MB.

## Options considered

1. **Full-window view inside the app** (like the File backstage). For: there is one window. Against:
   it hides the document you are working on, and the owner prefers a separate window.
2. **A separate page, `help.html`, opened in its own window.** For: you can read it next to the
   document; it has an address you can bookmark, share and print; it is light (no PDF engine).
   Against: it is a second Vite entry and needs a service-worker route.
3. **Screenshots by hand.** Against: they go stale and are inconsistent. **Generated by a
   Playwright script from the real app** instead: it is repeatable, needs one command, and uses
   self-made PDFs (rule 13).

## Decision

1. **D-46 Help window.** Help is a separate same-origin page, `/help` (`help.html`, a second
   Vite entry, `src/help/`), opened by Help → Help, **F1** and the "?" buttons with
   `window.open(…, 'triya-help', 'popup,…')` (a new tab if the browser refuses). It has a table of
   contents, task-oriented topics with screenshots, search on Enter (rule 3), print, deep links
   `/help#topic`, and follows the app's theme. The floating Help dialog is removed. The help page
   makes no network request apart from its own files, and never sees document content.
2. **Help strings** live in their own i18n namespace file, `src/i18n/help.en.json`, so the app
   bundle doesn't carry them. §8.2 now reads "`en.json` (and `help.en.json` for Help)". Every
   i18n rule and test applies to it.
3. **Screenshots** are generated by `npm run help:screenshots` (Playwright, Chromium, 1366 ×
   800, light theme, English, self-made sample PDFs), cropped, with numbered callouts drawn by an
   injected overlay, and encoded as WebP inside Chromium (no new dependency: `sharp` bundles
   LGPL libvips). They are committed under `public/help/img/`, and a unit test checks that every
   referenced image exists and has alt text.
4. **Offline.** The service worker serves `help.html` for navigations to `/help` and precaches
   the help entry and its images in the **background** group. `webp` is precached.
5. **Install budget is a reference (owner, 2026-11-07).** §9 changes from "Total install budget ≤
   60 MB" to "the install size is measured and reported per module in CI; about 60 MB is a
   reference, not a limit (the report warns, it does not fail)". The 9 MB core budget stays.

## Consequences

- The help can grow (more topics and images) without crowding the app bundle or a dialog.
- Screenshots need re-running after visible UI changes. The PR template gets a reminder; they
  are not compared pixel by pixel in CI.
- One more page for axe, the pseudo-locale and offline e2e to cover.
- ARCHITECTURE.md Rev 0.14: header amendment, D-46, §8 (Help), §8.2, §9 and §13 M9, applied
  when this ADR is accepted.
